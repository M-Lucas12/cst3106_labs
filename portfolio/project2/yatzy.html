1) Yatzy Game Summary

Yatzy is a dice game where players roll five dice up to three times per turn to achieve scoring combinations such as Three/Four of a Kind, Full House, Small/Large Straight, Chance, and Yatzy (five of a kind). My implementation focuses on clear state management, reusable UI components, and accurate scoring logic aligned with the assignment requirements.

2) Architecture & State

The Yatzy game follows a modular structure inspired by the MVC pattern. Each class handles a distinct responsibility — the game state, dice logic, and scoring system — making the app easier to extend and maintain.

GameState │ currentRoll: int (0..3) │ dice: List<Die> (5) │ scores: Map<Category, int?> │ availableCategories: Set<Category> └─ roll(), hold(index), score(category) Die │ value: 1..6 │ held: bool └─ toggleHold() Category │ ONES..SIXES, THREE_OF_A_KIND, FOUR_OF_A_KIND, FULL_HOUSE │ SMALL_STRAIGHT, LARGE_STRAIGHT, CHANCE, YATZY └─ compute(dice: int[5]) → int

3) Key Scoring Algorithms

The following core algorithms reflect the game logic I implemented in my assignments:

function fullHouse(dice): counts = sort(tally(dice).values()) return 25 if (3 in counts and 2 in counts) else 0
function smallStraight(dice): s = set(dice) return 30 if ( {1,2,3,4}.issubset(s) or {2,3,4,5}.issubset(s) or {3,4,5,6}.issubset(s) ) else 0
function yatzy(dice): return 50 if len(set(dice)) == 1 else 0

These examples demonstrate scoring logic for three major categories (Full House, Straights, and Yatzy). Each uses efficient state-based logic to compute player points.

4) Technologies & Best Practices

  • HTML/CSS: Semantic structure, comments, responsive layout (Flexbox, media queries).
  • JavaScript: Dice roll, state updates, and scoring functions.
  • MVC Concepts: Separation of data, UI, and logic for maintainability.
  • Accessibility (WCAG/ARIA): Landmarks, alt text, and focus order for usability.
  • GitHub: Version control, readable commits, and project tracking.

5) Reflection & Lessons Learned

  • Pure scoring functions made unit testing straightforward.
  • Separating logic from UI simplified adding features and debugging.
  • Accessibility and performance tweaks (alt text, smaller images) improved UX.
